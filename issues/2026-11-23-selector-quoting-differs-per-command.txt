What failed: the quoting rule is different per command, so every new flow trips on it.
  click/fclick/jclick/waitfor/find/scroll/...  take the rest of the line; quotes = hard error
  fill/date/m2o/celltype/boolcell              need 'quotes' around a selector with spaces
  mark                                         needs quotes, but an unquoted one only WARNS,
                                               then fails as "mark NOT FOUND"
  expect visible <sel>                         takes ONE token, so a selector with a space
                                               silently becomes selector + "expected" text
Run notes all blamed the flow ("my selector/quoting mistake"), so no issue was filed,
but it is the same kit trap every time. The 2026-08-06 quoted-click note fixed click only.

Workaround: rerun after reading the error.
Suggested fix: make every command accept a selector quoted OR unquoted.
  * rest-of-line commands: strip one pair of wrapping quotes instead of erroring;
  * selector + value commands: when the selector is unquoted and the next tokens look like
    more selector, use the longest prefix that actually matches an element (say so in the log);
  * expect visible/hidden: the whole rest of the line is the selector.
